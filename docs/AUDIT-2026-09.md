# Technical audit — September 2026

Baseline: `b30b91a` on `master`, last touched mid-2025.

At the start: `nx run-many --target=lint --all` failed, there was not a
single test in the repository, `npm audit` reported 103 advisories (7
critical), the deployed API signed JWTs with an empty secret, and the API
accepted any request body without validating it.

Now: lint reports zero problems, `tsc` runs in strict mode, 142 tests pass,
`npm audit --omit=dev` is clean, and both deploy workflows refuse to deploy
unless all of that passes. 23 commits.

This document was written after the first pass, when section 2 listed what had
been found and deliberately left alone. A second pass closed almost all of it;
section 2 now records what was done and why, and section 3 is what genuinely
remains.

---

## 1. Fixed

### 1.1 Authentication could be forged (critical)

`apps/api/.env.local` and `apps/api/.env.production` were committed, both with
`JWT_SECRET=criterium_secret_key`. The backend deploy workflow copied
`.env.production` onto the server, but `docker-compose.yml` passed
`JWT_SECRET: ${JWT_SECRET}` — a shell variable nothing on the server sets. The
old schema validated it as a bare `z.string()`, which accepts `""`. The
deployed API therefore signed and accepted tokens under an empty secret, so
anyone able to craft a JWT could mint an admin session.

Fixed: every `.env` untracked and ignored, `.env.example` added, the schema
requires ≥ 32 characters and rejects the previously committed value, and the
boot aborts otherwise. Both `""` and `criterium_secret_key` now have tests.

**The secret and the database password in the git history are burned. Rotate
both, and force every user to re-authenticate.**

### 1.2 No request validation at all (high)

`main.ts` installed a global `ZodValidationPipe`, but that pipe only validates
a parameter whose metatype is a class built by `createZodDto`. Every
controller declared plain interfaces, re-exported from `@app/shared` as
`export const XDto = {} as XDto` "for NX webpack compatibility", so the pipe
found nothing to validate. Four other DTOs carried `class-validator`
decorators, which were equally dead — no `ValidationPipe` was ever registered.

Measured on the running API before the fix:

```
POST /auth/register {"email":"not-an-email","firstName":"","lastName":"","password":"x"}
-> 201 Created, with a signed token
```

Fixed: `apps/api/src/common/dto` wraps every request schema in `createZodDto`;
`@app/shared` keeps the framework-free schemas the frontend shares. Same
request now returns 400 with a per-field error list. A test asserts every
exported DTO is a real `ZodDto`, so the regression cannot come back quietly.

### 1.3 Secrets baked into published images (high)

`backend.Dockerfile` took `JWT_SECRET`, `DB_PASSWORD` and the rest as build
args and promoted them to `ENV`, which writes them into image layers pushed to
`ghcr.io`. Removed; `docker image inspect` on the new image shows only
`NODE_ENV` and `BACKEND_PORT`.

### 1.4 Smaller security defects

| Defect                                                                       | Fix                                           |
| ---------------------------------------------------------------------------- | --------------------------------------------- |
| `RolesGuard` read `.role` off `undefined` when no user was attached          | denies instead                                |
| `JwtStrategy` put the full entity, password hash included, on `request.user` | hash stripped                                 |
| Bulk import created accounts with the literal password `defaultPassword123!` | random per account                            |
| No rate limiting anywhere                                                    | 120/min globally, 5/min on login and register |
| No security headers                                                          | helmet                                        |
| CORS origins hardcoded in source                                             | `CORS_ORIGINS`                                |
| Swagger served publicly in production                                        | off unless `SWAGGER_ENABLED=true`             |
| pino logged `authorization` headers and password fields                      | redacted                                      |
| `chmod -R 777` on the Postgres data directory                                | 700                                           |
| Postgres published on the host                                               | internal to the compose network               |

### 1.5 Dependencies

103 advisories (7 critical) → 15, none critical, **0 in production
dependencies**.

- `npm update` across the workspace: axios 1.10 → 1.20 (a long list of
  prototype-pollution and SSRF advisories), NestJS 11.1.3 → 11.2.5, TypeORM
  0.3.25 → 0.3.31, pg 8.16 → 8.23, class-validator, rxjs, react-query, radix,
  tailwind
- bcrypt 5.1.1 → 6.0.0, dropping the `@mapbox/node-pre-gyp` → `tar` critical.
  Verified that a hash written by bcrypt 5 still authenticates under 6
- Nx 21.1 → 23.2.1 via `nx migrate`, all 36 codemods applied. The nx packages
  had been split across two majors (`@nx/react` on 20.8, everything else on
  21.1)
- `@nx/react` dropped: nothing used it, and it dragged in module-federation,
  adm-zip, koa and ws
- nestjs-zod 4 → 5, dropping the `@nest-zod/z` fork
- `multer` overridden to ^2.4.0; `@nestjs/platform-express` 11.2.5 pins ~2.2.0,
  and all six remaining production advisories traced to it

### 1.6 Build and toolchain

- ESLint was split across two flat configs (root and `apps/web/`), so which
  rules applied depended on where lint ran from, and `nx lint` failed on
  master. One root config now, and lint passes
- `nx.json` used the deprecated `tasksRunnerOptions` block and pointed lint
  inputs at a `.eslintrc.json` that does not exist
- Three near-identical TypeORM data sources (`local`, `prod`, `migration`)
  collapsed into one. `synchronize` no longer keys off `NODE_ENV`; it is off
  everywhere and migrations are the only path
- `ConfigModule` read `envFilePath: '../.env.local'` — a path outside the
  repository, with the comment "Load .env.example for this test"
- `backend.Dockerfile` built on node:24 and ran on node:22, so bcrypt's native
  binding was compiled against a different major than the one loading it
- `start.sh` checked `$?` after a command under `set -e` and offered to
  "continue anyway" on a failed migration — unreachable, and the wrong
  behaviour regardless
- `dotenv` was imported but never declared as a dependency

### 1.7 CI/CD

- Nothing was verified before deploying. `ci.yml` now runs lint, tests, build
  and a production audit, and both deploy workflows depend on it
- The deploy workflows ran `rm -rf node_modules package-lock.json && npm
install`, so every deploy resolved a fresh dependency tree — what shipped
  was never what anyone tested
- The frontend workflow filtered on `'../../apps/web/**'`, which matches
  nothing, so frontend-only changes never deployed. It also deployed
  `docker-compose.prod.yml`, a file that is not in this repository
- `docker system prune -af` on a shared host deleted images belonging to other
  stacks → `docker image prune -f`
- Actions bumped from v2/v3 to current majors
- `nginx.Dockerfile` copied a full `http{}` block into `conf.d/`, where nginx
  expects a server block; nothing used the image. Removed
- `docker-compose.local.yml` referenced `Dockerfile.dev.web`, which does not
  exist

### 1.8 Tests

57 tests, from zero: the env schema, `RolesGuard`, `JwtStrategy`,
`AuthService`, `UsersService`, the request DTOs, the shared auth and
pagination contracts, and the frontend `cn` helper.

The pagination test found a live bug on the way in: `PaginationDtoSchema`
demanded `z.number()` while query strings arrive as text, so `?page=2` could
never have validated once validation started working.

## 2. The second pass: what section 2 used to list

Everything below was "found, not fixed" after the first pass. This is what
happened to it.

### 2.1 LLM spend was under-reported — fixed

There were two OpenAI clients; only one recorded cost, and the bulk assessment
path used the other. They are one service now, every call is recorded, cost is
attributed to the model the API reports back rather than the one requested,
and the duplicated pricing table in auto-assessment is gone. The standing TODO
about retries is done: three attempts with backoff on 408/409/429/5xx, none on
a 4xx the server rejected on its merits.

Fixing it also surfaced that `parseAssessmentResponse` invented scores when a
model reply would not parse — a missing `totalScore` became 5 — writing
fabricated marks into the database as if the model had produced them. A
malformed response now scores nothing and says so.

### 2.2 Imported students could not sign in — fixed

An administrator issues a one-time link
(`POST /api/v1/admin/users/:id/password-reset-link`): 24 hours, single use,
only the SHA-256 stored, issuing a new one retires the old, and every failure
returns the same message so the endpoint cannot be used to probe for accounts.
`/set-password` redeems it. There is deliberately no self-service "email me a
link": this application has no mail transport, and a flow that cannot deliver
is worse than none.

### 2.3 TypeScript was effectively off — fixed

`strict: true`. The one exemption is `strictPropertyInitialization`, off
because TypeORM hydrates entity properties after construction — that was 146
of the 185 errors. The other 39, plus 11 in the frontend, were real: unchecked
nulls after a re-read, mappers annotated as non-nullable while returning null,
`catch (error)` sites reading `.message` off `unknown`, a cost table indexed
without an index signature, form state typed as a partial-update request.

`@typescript-eslint/no-explicit-any` is an error and the workspace is at zero.

### 2.4 The `{} as T` DTO stubs — removed

All 35. Removing them is what prompted smoke-testing every route, which found
the three defects in section 2.11.

### 2.5 Frontend bundle — fixed

One 1.40 MB / 327 kB gzipped bundle became 62 chunks with a 562 kB / 170 kB
shell; React, Router and Query are split out so a deploy does not invalidate
the framework a returning visitor has cached. Zod was in the browser bundle
because the only runtime value the frontend takes from `@app/shared` is the
`UserRole` enum and it was imported from the barrel; those imports point at
`@app/shared/interfaces` now. Two dependencies nothing imported were dropped.

### 2.6 Tokens in `localStorage` — fixed

The session is an httpOnly, SameSite=Strict cookie; the token is never in a
response body. Writes carry a double-submit CSRF token, checked only on
cookie-authenticated requests. `POST /auth/logout` clears the session
server-side, where before "logout" deleted a `localStorage` key.

### 2.7 The OpenAI key was plaintext in the database — fixed

AES-256-GCM under a validated `SETTINGS_ENCRYPTION_KEY`, with a version prefix
so values written by an older release are recognised and re-encrypted on the
next save. `GET /settings` returns a mask; posting the mask back no longer
destroys the key. The OpenAI client is cached against the key it was built
with, so a rotation takes effect on the next call.

### 2.8 The `/api` prefix was unaccounted for — fixed

`setGlobalPrefix('api')` plus URI versioning, so every route is `/api/v1/...`,
and nginx in the frontend image proxies `/api` to the backend on the same
origin. `/health` stays outside both. One error shape for the whole API.

### 2.9 NestJS 12 — done, by removing the thing that blocked it

`nestjs-zod` gave the project three things - `createZodDto`, a validation pipe
and an exception - and in exchange pinned `@nestjs/swagger` to `^11`, which
held the whole application on NestJS 11. The three are about 150 lines, now in
`apps/api/src/common/zod`, with OpenAPI metadata derived from Zod 4's own
`z.toJSONSchema`. The dependency is gone and the stack is on NestJS 12,
Swagger 12 and Zod 4.

### 2.10 The smaller items — done

`apps/web/package.json` is gone and the workspace has one manifest; lint is at
zero; the webpack step that copied raw `.ts` migrations into `dist` is gone;
admin list endpoints are capped at 100 rows and 365 days.

Vitest is still pinned to 3.x: npm 10.9.8 crashes resolving vitest 4's peer
set with "Cannot read properties of null (reading 'edgesOut')". Twelve
dev-only advisories remain in the Nx toolchain, none reachable at runtime.

The Bruno collection was stale in a way that would have misled anyone using
it: no `/api/v1`, bearer tokens that are no longer how sessions work, and an
assertion that the login response contains `access_token`. Updated.

### 2.11 The language-model client is no longer an OpenAI client

The likely model is DeepSeek, probably through OpenRouter, and that is not
settled. It does not need to be: those providers all speak the same
chat-completions protocol, so the `openai` package is the protocol client and
the provider is an administrator setting - key, model, base URL, price
overrides. Adding another OpenAI-compatible endpoint is an entry in
`providers.ts`.

The pricing table needed rethinking rather than renaming: anything not in it
used to fall back to an invented rate, which put made-up numbers in the cost
report. An unknown model now records its tokens at zero cost with
`costKnown: false` and a warning naming it.

### 2.12 Things the second pass found on its own

None of these were in the first audit.

- **The frontend's entire theme layer generated no CSS.** Tailwind v4 takes
  its scale from `@theme`, and the design tokens were only declared as loose
  CSS variables, so 550+ uses of `bg-card`, `text-muted-foreground`,
  `border-border` and friends compiled to nothing. Only hardcoded colours ever
  reached the screen — which is why the UI looked the way it did. Dark mode was
  dead too: the variant compiled to `@media (...) or .dark`, not a valid media
  query, so browsers dropped the block and all 90 `dark:` utilities with it.
  Every Radix animation was inert as well.
- **The assessment-sessions feature had never worked.** `AutoAssessment`
  selected camelCase columns the migration had created as snake_case;
  `GET /auto-assessment/:id` was declared above `/sessions` and swallowed it;
  and `assessment_sessions` and its entity were two different designs, so every
  read failed. Three fixes and one migration.
- **A password-hash leak.** An assessment session's response embedded its
  `initiatedBy` user in full, bcrypt hash included, to anyone with reviewer or
  admin. `User.password` is `select: false` now; one lookup asks for it by
  name, and only login uses that.
- **`CreateReviewPage` could not render.** Its `task` state was never set, so
  the criteria scoring form and the submit button were behind a condition that
  was always false. `SolutionDetailPage` read criterion names off a nested stub
  the API does not send, and silently showed "Criterion 1", "Criterion 2".
- **`BulkImportPage`'s two template buttons had no handler.**
- **Three near-identical migration runners, a third of a test suite of
  build artifacts committed next to sources, and 474 lines of stale agent
  rules.** All removed in the tidy pass.

## 3. What still remains

Ordered by what I would do next.

1. **Self-service password reset.** The token service is built and tested; it
   needs an SMTP client and a "forgot password" endpoint that does not
   enumerate accounts. Today an administrator has to hand the link over.
2. **The Academy integration** — see `docs/ACADEMY-INTEGRATION.md`. Nothing is
   built; the note records the shape, the scopes and the four decisions that
   have to be made first.
3. **Nest integration tests.** The 142 tests are unit tests: no test boots the
   Nest container or drives a real HTTP request, so guards, pipes and the
   exception filter are covered by reasoning and by hand. Vitest's esbuild
   transform emits no decorator metadata, so this needs `unplugin-swc` or a
   separate jest project.
4. **The shell bundle is still 170 kB gzipped.** Route splitting took the big
   win; what is left is the layout, contexts, axios and the Radix primitives
   the shell itself uses. Worth a bundle analyser pass, not guesswork.
5. **`@Exclude()` on `User.password` is now redundant** with `select: false`
   and could go, along with the `class-transformer` dependency if nothing else
   uses it.
6. **The audit middleware logs a response summary for every request.** With
   retention unbounded, `audit_logs` grows without limit. It needs a retention
   policy, or at least an index-backed purge job.
7. **Rate limiting is in-process**, so N replicas mean N times the configured
   limit. A shared store would fix it and is the one thing that would add
   Redis to this stack.
8. **LLM assessment runs in-process**, started by a request and continuing
   after the response. A container killed mid-run leaves the operation marked
   in progress. This wants a real job queue.

## 4. How this was verified

- `npm run verify` — lint, typecheck, 142 tests and the production build —
  passes, and is what CI runs
- `npm audit --omit=dev --audit-level=high` passes
- the API was run against a throwaway Postgres: migrations apply, register,
  login and profile work, a student gets 403 on an admin route, the sixth
  login attempt in a minute gets 429, invalid bodies get 400, and booting with
  the old secret aborts
- `docker compose up --build`: postgres healthy, backend healthy, migrations
  applied, `/health` and `/health/ready` answer, Swagger 404s in production,
  the frontend serves with gzip, immutable asset caching and security headers
- `docker image inspect` confirms no secrets in the backend image
- eleven API routes answered 200 against a real database after the strict
  pass and again after the `any` purge
- the session model was exercised in a browser: the session cookie is absent
  from `document.cookie`, `localStorage` holds nothing, a write without the
  CSRF header is 403 and with it 200, and after logout the profile call is 401
- the reset-link flow end to end: an imported account with a random password
  received a link, set a password, signed in, and the same link failed on
  reuse; the database row holds only the hash
- `GET /settings` returns `sk-••••••••cdef` while the stored row is
  `enc.v1.…`, and posting the mask back leaves the key intact
- the redesign was opened screen by screen in both themes; a contrast sweep
  over every text colour against its real background reports no WCAG AA
  failures
- route splitting was confirmed in the browser: `/dashboard/tasks` loads 16
  chunks and the admin panel is not among them
